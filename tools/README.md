# `tools/` — regression harnesses

Run-from-the-repo-root harnesses (inside `nix develop`). Except where noted they are
**not yet wired into CI** — run them before landing changes to the native backend /
link step / FFI. Wiring the rest into a CI job (one that has the Level-2 CLI built, the
runtime staticlib, staged ulib, `clang`/`llvm`, and `cargo`) is an open follow-up; see
the note at the bottom.

| Harness | Guards | Needs |
|---|---|---|
| `l2-native-behavioural.sh` | The ADR-0104 §2 **Level-2 native behavioural gate** (standing net; **CI-wired**: `l2-behavioural-ci.yaml`): behavioural fixtures (`test-fixtures/l2-behavioural`) compiled by Level-2 to native binaries, run under a small `PURVASM_HEAP_WORDS` in both `--opt`/`--no-opt`; stdout ≡ oracle (frozen boot VM + fixture-owned expected traces), stats schema-checked with `gc_collections >= 1` (forced-GC coverage cannot go vacuous). ADR-0105 slice 0 added the **GC-stress legs** (same binaries under `PURVASM_GC_STRESS=1` — every allocation collects — additionally asserting `gc_copied_words > 0`) and the **debug-ABI-profile leg** (`Gate.RootStress` as entry-call IR via `PURVASM_EMIT_DEBUG_ABI=1`, linked against the **debug** runtime staticlib, stamp-audited, run under stress). | boot, runtime `.a` (release **and** debug), staged ulib (`dist/ulib`), `clang`, `node`, `nm`, workspace `spago build` |
| `selfhost-fixpoint-diff.sh` | The ADR-0104 §2 **self-host fixpoint** (milestone gate): boot seeds `C2` (bytes excluded) → `C2` compiles the pinned closure → stage-3 artifacts + `C3` → `C3` compiles the same closure → stage-4; asserts stage-3 ≡ stage-4 byte-for-byte over every `.ll`, `entry.ll`, `.pmi` (inputs snapshotted; comparison set allowlist-validated). Profiles: `smoke` (`--no-opt`, default) / `milestone` (`--opt`, the required profile — currently **blocked + non-blocking under an explicit maintainer waiver**, ADR-0104 §2 amendment 2026-07-19: `smoke` is the operative gate meanwhile, and each release/ADR-landing checkpoint records a bounded `milestone` re-attempt + the waiver until the tracked perf blocker is resolved). | boot, runtime `.a` (release), staged ulib (`dist/ulib`), `clang`, `node`, workspace `spago build` |
| `native-run-diff.sh` | ADR-0082 native **execution** differential: `Prim`-only fixtures built to a native binary by **both** boot and Level-2, run, and asserted equal. Codegen → `clang` → link → run. | boot, runtime `.a`, `clang`, `purs`, `node` |
| `llvm-diff.sh` | **RETIRED from standing use** (ADR-0104 §4): boot-vs-Level-2 byte-identical `.ll` — fails by design after the first intentional divergence (§3 bridge removal). Kept as a bisection aid against pinned history; see its header. | boot, `purs`, `node` |
| `byneed-census.sh` | ADR-0107 **by-need demand-site census** + its accounting gate (measurement harness, manual milestone; its `bash -n` syntax check is **CI-wired** in `purescript-ci.yaml`). Snapshots the inputs into `$WORK` — the compiler's own compiled JS and the CoreFn closure SEPARATELY, since `output/` is both and `--corefn-dir` must not be silently ignored — then runs two legs from the snapshot: a real `--emit-llvm` build and the `census byneed` tool. Gate: for EVERY emitted object, the census's emitted occurrences == `fchk` force chains in its `.ll` (303/303 exact). With `BYNEED_ACCOUNTING=1` a third, counterfactual leg (`PURVASM_BYNEED_OFF=1`) runs and the ADR-0107 §2 identity is checked: deleted chains == elided occurrences. `--opt` (default path) / `--no-opt` (reference lowering) are separate runs and give materially different `Never` shares by design. | staged ulib (`$PURVASM_LIB`, default `dist/ulib`), `node`, workspace `spago build` |
| `apply-census.sh` | ADR-0108 §2 **apply census** + its six-column accounting gate (measurement harness, manual milestone; `bash -n` **CI-wired**). Snapshots the inputs, then runs a real `--emit-llvm` build and `census apply`, which reads the classification events the emitter recorded while emitting the SAME objects. Gate, per object: `pv_apply == generic-apply + structural-apply`, `pv_tailcall == generic-tail`, `musttail == direct-musttail`, `guestDirect == direct-nontail + wrapper-entry` (304/304 exact). Counting caveats are in its header — including that the corpus is the compiler, so an LLVM-emitting module carries the emitted syntax as string constants. `--toolchain DIR` runs it from a caller-pinned `{output,cli,census,ulib}` snapshot with no build and no re-snapshot, so a long-running caller can guarantee the census and its subject share ONE compiler. | staged ulib (`$PURVASM_LIB`), `node`, workspace `spago build` |
| `apply-profile.sh` | ADR-0108 §3 **dynamic apply profile** + its reconciliation gate (measurement harness, manual milestone; `bash -n` **CI-wired**). Inputs snapshotted into `$WORK` (all legs run from the copy, so a concurrent build cannot leave per-fixture identities green while the AGGREGATE mixes runs of different programs). The same classifier that labels a site at emission time bumps a per-`(form × reason)` counter at run time; the gate is EXACT, never a tolerance: `Σ generic-apply/<reason> + structural-apply == pv_apply_entries` and `Σ generic-tail/<reason> == pv_tailcall_writes` — the instrumentation against counters the runtime already kept for its own reasons. Also asserts what instrumentation must NOT do (instrumented output ≡ uninstrumented) and refuses a vacuous 0-dispatch run. **ADR-0108 §4 drill**: foreign dispatches are additionally counted by `<symbol>|<form>|<arity-status>` through a KEYED counter (`purvasm-applyprofile-keys:v1`), gated by a cross-mechanism identity — `Σ keys == the callee-foreign slots` — since keys and slots are written down different paths. That gate is UNCONDITIONAL (absent keys are Σ0, correct only against 0 slots) and `--self-test` injects six faults — including the whole key schema vanishing — and asserts its verdict; it needs no build, ulib or runtime, so it is **CI-wired as a test**, not just a syntax check. **Two workloads:** fixtures (fast, `--opt`; their ranking describes THOSE programs) and **`--selfhost`** — the ADR's headline workload: the compiler itself built instrumented, compiling the pinned closure, with the emitted `.ll` set diffed against a node-hosted reference. `--selfhost` then runs `apply-census.sh` over **its own snapshot, with its own pinned toolchain** (`--toolchain`: nothing rebuilt, nothing re-copied — the classifier is an input too, and the earlier legs take hours) and prints sites and executions in ONE table with an `exec/site` ratio: both harnesses snapshotting `output/` separately is *not* one corpus (`output/` holds the compiler's own CoreFn, so any `spago build` in between changes the measured program — two such snapshots differed in 85 files), and the census is taken in `--build-mode` because the sites in the running binary are the sites of the compiler as it was BUILT. Two mode axes, deliberately separate: `--build-mode` (the running compiler's own build = the CORPUS, match the census's `--opt`) and `--work-mode` (what it compiles = the WEIGHTS; `--no-opt` by default under `--selfhost`, since native whole-closure `--opt` is still under the ADR-0104 §2 waiver). | staged ulib (`$PURVASM_LIB`), runtime `.a` (release), `clang`, `node`, workspace `spago build` |
| `byneed-ab.sh` | ADR-0107 slice-1 **run-time A/B** (measurement harness; owed follow-up, needs a quiet machine — see the ADR). The same benchmark program built twice by the same Level-2 compiler with the lattice ON and OFF, from snapshotted inputs, with every measurement knob harness-owned, each run's exit status required, a program whose `fchk` count does not drop refused as NO-ELISION, and the statistic reported as the MEDIAN of order-alternated PAIRED ratios with their range. Neither `run-benchmarks.sh` (its `llvm` leg builds with **boot**) nor `paired-ab.sh` (varies the runtime staticlib) can see a Level-2 emitter change. | staged ulib, runtime `.a` (release), `clang`, `node`, `perl`, workspace `spago build` |
| `foreign-sigs-diff.sh` | FSR (ADR-0080) foreign-signature reconstruction vs boot's registry. | boot, `purs`, `node` |
| `ffi-e2e.sh` | ADR-0091 **user-defined native FFI**: app-C sibling `.c` (`PVF_EXPORT` + `-DPVF_MODULE`) and app-Rust `--rust-ffi` crate (`purvasm-bundle` cargo build + `nm` audit) built to a native binary, run, asserted `== 42`; plus two negative cases (a C sibling in a Rust workspace → C-xor-Rust ambiguity; `--runtime-lib` + `--rust-ffi` → rejected). The app-Rust *happy* leg is **skipped** (not failed) without `cargo`; the negatives always run (they error before any bundle build). | runtime `.a` + `purvasm.h`, staged ulib (`$PURVASM_LIB`), `clang`, `purs`, `node`; app-Rust also `cargo` + the runtime crate (`$PURVASM_RT_CRATE`, else `runtime/`) |
| `elf-export-probe.sh` | ADR-0111 §1.1's **owed ELF measurement** (**CI-wired**: `vm-loader-ci.yaml`, and always run — it needs nothing built). A two-file linker experiment varying only how a host exposes its symbols, so each export mode (none / version script / `--export-dynamic` + version script / `--dynamic-list`) gets an independent verdict on four questions, kept apart on purpose: **RETAINED** (is the `-u`-only archive symbol in the ordinary symbol table — the ADR's owed `--gc-sections` claim, which the `none` row states in isolation), **EXPORTED** (is it in `.dynsym`, which is a different question — an executable may legitimately contain a symbol it does not export), **LEAKED** (is an unrelated host function in `.dynsym` too), **DLOPEN** (does a provider referencing it load under `RTLD_NOW`). Expectations are pre-committed, so a mode that starts or stops working fails the harness rather than scrolling past. **Measured 2026-08-18** (clang/LLD 21.1.7 + GNU ld 2.44): retention holds in every row including `none` — settling ADR-0111 §1.1's owed `-Wl,-u` + `--gc-sections` claim — while a version script alone exports **nothing**, which is why the ELF branch of the link is `--dynamic-list`. **SKIPs (exit 0) on non-ELF hosts.** | `clang`, `ar`, `nm` (a Linux host; nothing else) |
| `vm-loader-e2e.sh` | ADR-0111 slice-1 **loader gate** (**CI-wired**: `vm-loader-ci.yaml`): the owned VM (ADR-0110) built with `--host-foreign-api`, then handed providers built as shared objects. Four sections and nine assertions, none visible to a unit test. **The export set** (§1.1, the *negative* direction): the generated allowlist and the executable's actual dynamic export set must match EXACTLY, in both directions — a re-exported `pvf_Purvasm_2eVM_2eLoader_2e*` or `pv_g_*` is named as a trusted-surface failure, since a guest could then `foreign import` the trusted loader itself (§6). Every other leg is positive, so nothing else here can see that regression; measured against a VM built without `--host-foreign-api`, this leg reports 629 exported against a 57-symbol allowlist, including all 5 loader leaves. **Retention/export** (§1.1): a fixture referencing *every* `pv_*` in `purvasm.h` must load — `RTLD_NOW` binds every reference, so a symbol the link dropped fails by name, where a VM that never calls that API would otherwise link, run and pass everything else. **Runtime leaves** (§1.1/§2): the corpus's own providers live in the runtime staticlib the VM already links, so `show` and stdio resolve through `host-runtime` with **no module loaded and no manifest**; the guest program applies `show` to 42, passes the resulting carrier to `writeLine` undecoded, runs the effect thunk, and must print 42; `floatBitsHi 1.0` must print 1072693248 (0x3FF00000 — a wrong `Number` representation could not produce it by chance); the entry must still report the leaf's result as a carrier rather than a string; and a key mentioned at two arities must be refused as a corrupt image, run as its own process because a stuck run cannot be caught in-process (ADR-0074's throw-only `Effect.Exception`). **The foreign-ABI version contract** (§5): ONE fixture built twice — against the shipped header and against a copy with `PV_FOREIGN_ABI_VERSION` bumped — announcing itself from a module initialiser; the current-version build must load *with* the marker (which is what makes its absence mean something), the bumped one must be refused *without* it, since `dlopen` runs initialisers before returning. **Diagnosis** (§5): a provider missing an *unrelated* host symbol, built under the filename `pv_foreign_abi_v99-bad.so` — `dlerror()` reports the provider path beside the unresolved symbol, so a loader that read the whole message could be steered by a filename into blaming the ABI; the refusal must name the symbol that is actually missing. | runtime `.a` + `purvasm.h`, staged ulib (`$PURVASM_LIB`), the VM's CoreFn (`spago build -p vm`, `$COREFN_DIR`), `clang`, `node` |

`native-run-diff.sh` covers only `Prim`-only pure values (no foreign providers), so
`ffi-e2e.sh` is the counterpart that exercises the whole native-FFI provider-map path.
`ffi-e2e.sh` and `vm-loader-e2e.sh` are the two halves of the same claim — one provider
source, linked statically into a program and loaded dynamically by the VM.

## CI-wiring follow-up

`vm-loader-ci.yaml` wires the two loader harnesses above, and does so for a reason beyond
tidiness: the retention/export mechanism was measured on Mach-O only (ADR-0111 §1.1's
Correction), so the ELF half is not a second platform to tick off — it is where the
recipe may simply differ. Its `elf-probe` job is the isolated measurement; the `loader`
job is the same gate the maintainer runs locally.

`ffi-e2e.sh` and `native-run-diff.sh` are the two that assert Level-2 native execution;
neither runs in CI today. `.github/workflows/examples-ci.yaml` already crosses the full
toolchain (runtime build + ulib stage + `cargo`/`clang` + `spago build`, which builds the
Level-2 CLI) but is scoped by design to the boot-driven examples sweep ("Level 2
excluded"). Wiring these two in — either as a step there (`PURVASM_LIB=dist/ulib`,
`PURVASM_RT_A=runtime/target/release/libpurvasm_rt.a`) or as a small dedicated job — is a
CI decision for the maintainer, tracked here so the harnesses are a fixed target, not a
forgotten script.
